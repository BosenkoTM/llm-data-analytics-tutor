# Проект API и модели данных

Проектные сущности расширяют существующую схему после её обследования. Это не готовая миграция.

| Сущность | Ключевые поля и ограничения |
|---|---|
| documents | document_id; название; тип; авторы; publication_date; JSONB для дополнительных атрибутов; published_version_id |
| document_links | document_id; rag_key; activity_id; связь с существующим каталогом без копирования дисциплин |
| document_versions | version_id; document_id; version_no; UNIQUE(document_id, version_no); bucket; object_key UNIQUE; original_name; MIME; size; SHA-256; автор и дата |
| Статусы версии | storage_status: uploading/stored/failed; index_status: pending/processing/ready/failed; publication_status: draft/published/archived |
| chunks | chunk_id; version_id; текст; tsvector; embedding; page или section/paragraph; идентификатор модели |
| processing_jobs | job_id; version_id; тип; статус; attempts; next_retry_at; безопасное описание ошибки; ключ идемпотентности |
| audit_events | субъект; действие; document_id; version_id; время; результат |

Ключ MinIO: documents/{document_id}/{version_id}/original.ext. Идентификаторы генерирует сервер. Оригинальное имя хранится отдельно. Bucket закрытый. Ни полный файл в JSONB, ни публичная постоянная ссылка в каталоге не требуются.

Опубликованная версия и её указатель меняются в транзакции PostgreSQL. Для поисковой видимости необходимы storage_status=stored, index_status=ready, publication_status=published и разрешение пользователя. Файлы могут публиковаться для скачивания без RAG; флаг использования в RAG независим от видимости и не отменяет ACL.

Перед удалением объектов проверяются ссылки и задания. Удаление не должно выполняться как автоматический каскад без согласованной политики хранения. Резервное копирование включает PostgreSQL, объекты MinIO и проверку их связности.

## Прослеживаемость первоисточника в контексте конференционного исследования

Архитектурная часть конференционного доклада «Организация информационного обеспечения RAG-систем» задаёт сквозной инвариант: найденный фрагмент должен ссылаться на **конкретную неизменяемую версию** оригинала, а не только на название документа или последнюю опубликованную версию. Программная реализация этого инварианта относится к ВКР.

Поисковая выдача в проектируемом API должна содержать `document_id`, `version_id`, наименование документа, метаданные допустимой публикации, релевантный фрагмент (с указанием его положения) и разрешённое действие получения файла. Результаты гибридного поиска агрегируются на уровне версии документа до объединения RRF; `version_id` используется и при повторной проверке доступа, и при скачивании. Если новая версия опубликована, старые поисковые связи не должны незаметно переключаться на её объект.

Это **контракт проектного решения**, а не утверждение о наличии работающих конечных точек. Состав полей и миграции уточняются после обследования исходной схемы БД и проверки фактического API.

## 8 Функциональные требования
Методист выбирает существующую дисциплину и занятие, открывает вкладку «Документы», задаёт описание и прикрепляет PDF/DOCX. Интерфейс показывает имя файла, размер, версию, видимость, состояние обработки и действия: скачать, загрузить новую версию, опубликовать, снять с публикации.
Студент видит опубликованные доступные документы, ищет по словам и смыслу, применяет фильтры и скачивает оригинал. Закрытые преподавательские решения не попадают в выдачу, сниппеты и контекст LLM. Проверка прав выполняется при поиске и повторно при скачивании.
| Проектный метод API | Назначение |
|---|---|
| POST /api/v1/documents | Создать карточку и загрузить первый оригинал |
| POST /api/v1/documents/{id}/versions | Загрузить новую неизменяемую версию |
| GET /api/v1/documents | Получить доступный каталог с фильтрами |
| GET /api/v1/documents/{id}/versions | Получить разрешённые сведения о версиях |
| POST /api/v1/versions/{id}/publish | Опубликовать версию по правилам доступа |
| POST /api/v1/versions/{id}/unpublish | Снять версию с публикации |
| GET /api/v1/versions/{id}/download | Проверить права и выдать файл |
| POST /api/v1/versions/{id}/reindex | Повторить индексирование |
| POST /api/v1/search | Поиск fulltext, vector или hybrid |
API не принимает роль и права доступа из произвольных полей клиента: они определяются по проверенной пользовательской сессии. HMAC запуска Moodle не заменяет авторизацию на документ. Фильтры rag_key и активности проверяются на сервере.
В базовом прототипе скачивание выполняется через сервис, который читает объект из закрытого MinIO и передаёт поток пользователю. Такой вариант позволяет проверять права при каждом запросе. Временные подписанные ссылки — необязательное расширение с явно заданным сроком действия.
Устанавливаются проверяемые ограничения MIME-типа и размера, например 50 МиБ на файл для стенда. В журнал не записываются содержимое документов, секреты или временные ссылки доступа. Архивирование документа сохраняет историю и исключает его из новой поисковой выдачи.
