# 02. Компоненты и зоны ответственности

Система разбита на физически разделённые модули с чётко очерченными границами. Каждый агент
является самостоятельным сервисом и одновременно **MCP-клиентом**: он подключается к слою MCP,
выполняет discovery доступных инструментов и решает, что вызывать. Языковая модель остаётся в
бэкенде — данные не покидают контур вуза.

## Таблица модулей

| Модуль | Роль | Зона ответственности |
|---|---|---|
| `copilot_ui` | Презентация | Веб-интерфейс на Next.js + CopilotKit: чат, меню выбора агента, генеративный UI (структурированные карточки результатов), кнопки Human-in-the-loop. Маршрутизирует запрос к нужному агенту по идентификатору. |
| `agent_tutor` | Оркестратор (студент) | Граф LangGraph Тьютора. Обычный чат (RAG + ответ модели) и «режим агента» (пре-валидация кода, генерация заданий через MCP). Оценивание недоступно. |
| `agent_assistant` | Оркестратор (преподаватель) | Граф LangGraph Ассистента. Проверка присланной работы, предварительная оценка по рубрике, Human-in-the-loop, запись трассы. |
| `mcp` | Ядро «агент ↔ инструменты» | MCP-сервер, объявляющий примитивы протокола. Содержит подпапки `tools`, `resources`, `prompts`, `sandbox` (см. ниже). |
| `mcp/tools` | Действия | Инструменты `validate_code`, `generate_task`, `write_trace`, `grade_submission`. Контракты — в [04_mcp_tools.md](04_mcp_tools.md). |
| `mcp/resources` | Данные для чтения | Ресурсы `materials://` (материалы курса из RAG), `rpd://` (рабочая программа дисциплины), `rubric://` (рубрики оценивания). |
| `mcp/prompts` | Шаблоны ролей | Системные роли `tutor_system` и `assistant_system` (тексты-ядра не публикуются). |
| `mcp/sandbox` | Изоляция исполнения | Безопасный прогон Python/SQL с таймаутом и лимитами ресурсов, без доступа к сети. |
| `shared` | Общий слой | Конфигурация, схема и инициализация БД, префлайт-проверки, вспомогательные функции RAG. |

## Границы между модулями

- **`copilot_ui` ↔ агенты** — по протоколу AG-UI. Интерфейс не содержит бизнес-логики
  оценивания или проверки кода; он только отправляет запросы и рендерит структурированные
  ответы.
- **Агенты ↔ `mcp`** — по MCP (JSON-RPC 2.0) поверх транспорта stdio (локально) или
  Streamable HTTP (по сети). Агент — клиент, MCP-сервер — поставщик инструментов, данных и
  шаблонов. Ни один агент не обращается к песочнице напрямую, только через инструмент
  `validate_code`.
- **`mcp` ↔ инфраструктура** — MCP-сервер инкапсулирует доступ к RAG-хранилищу (pgvector),
  файлам рабочих программ и рубрик, а также к песочнице исполнения.
- **`shared`** — общий, не содержащий сетевых эндпоинтов слой; используется и агентами, и
  MCP-сервером во избежание дублирования логики.

## Модульность и расширяемость

Система стартует с одним MCP-сервером. Структура позволяет добавить новые MCP-серверы
(например, модуль расписания/РПД или балльно-рейтинговой системы) **без переписывания ядра** —
новый сервер просто регистрируется у клиента-оркестратора.

## О сетевых параметрах

Каждый сервис (интерфейс, агенты, MCP-сервер, инфраструктура) слушает свой сетевой порт.
В публичной документации конкретные порты и хосты не приводятся: они задаются в приватной
конфигурации развёртывания. Везде, где требуется указать порт, используется плейсхолдер
`<port>`, а хост — `<host>`.
