# 7. Автотесты и интеграция (Фронт + Бэк + БД)

## Цель комплексного E2E-сценария

Проверить связку **UI → сервер Loader → векторное хранилище** на одном учебном документе:

> Преподаватель загружает тестовый материал с метаданными → выполняет предпросмотр →
> подтверждает запись → в хранилище знаний появляются новые фрагменты с ожидаемым курсом/темой.

Инструменты (рекомендация): автоматизированный браузерный тест + проверка состояния БД.
Конкретные селекторы UI, имена колонок и полный тест-раннер **не публикуются**.

## Сценарий E2E (логически)

| # | Действие | Ожидание |
|---|---|---|
| 1 | Открыть UI Loader | Сервис доступен, хранилище в статусе «готово» |
| 2 | Приложить тестовый учебный файл | Файл принят формой |
| 3 | Запустить **предпросмотр** | Показаны фрагменты; число строк в БД **не** выросло |
| 4 | **Подтвердить** запись | Сообщение об успехе |
| 5 | Проверить хранилище по тестовой теме | Число фрагментов увеличилось, курс совпал |
| 6 | (Опционально) Повторная загрузка | Политика антидублей сработала |

### Иллюстрация фикстуры (обезличено)

```markdown
---
course: <course_key>
material_type: lab
topic: e2e_demo_topic
---

Краткий учебный текст для проверки пайплайна индексации…
```

### Иллюстрация проверки (псевдокод)

```python
def test_preview_then_commit(ui, db):
    before = db.count(topic="e2e_demo_topic")
    ui.upload_fixture("sample.md")
    ui.run_preview()
    assert db.count(topic="e2e_demo_topic") == before
    ui.confirm()
    assert db.count(topic="e2e_demo_topic") > before
```

## Критерий приёмки

E2E успешен, если есть три артефакта (CI + фронт + БД) и инвариант:
**предпросмотр не меняет объём индекса, подтверждение увеличивает его** для тестовой темы.
