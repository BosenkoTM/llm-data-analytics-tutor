# 2. Оригинальность идеи

## Чем отличаются аналоги

| Класс решений | Типичный подход | Ограничение для вуза |
|---|---|---|
| Облачные «knowledge bases» | Загрузка файлов во внешний сервис | Данные курса покидают контур вуза |
| Универсальные ETL-оркестраторы | Скрипты инженера данных | Нет педагогического UX, высокий порог входа |
| Встроенный поиск LMS | Полнотекст / ключевые слова | Нет dense-эмбеддингов и единого ingest-контракта с тьютором |
| Разовые notebook-пайплайны | Локальные `.ipynb` | Нет безопасного цикла «просмотр ≠ запись», нет единой схемы курса |

## Что предлагаем нового

1. **Педагогический контракт контента.** Один документ ≈ одна тема; метаданные курса и темы
   становятся частью учебного артефакта, а не «полей, забытых на форме».
2. **Безопасный цикл записи: предпросмотр → подтверждение | отмена.** Индекс не обновляется
   до явного решения преподавателя — в отличие от схемы «загрузил = сразу записал».
3. **Чанкинг с учётом учебных материалов с кодом.** Границы фрагментов сохраняют целостность
   блоков программного кода в Markdown — важно для курсов Python/SQL.
4. **Разделение ingest и inference.** Loader — слой наполнения; EduTutor / MCP только читают
   индекс — роли сервисов грантового контура чётко разделены.
5. **Комплекты шаблонов по дисциплине.** Снижает стоимость подготовки материалов для двух
   целевых курсов магистратуры.

## Инновационность модели

Модель «преподаватель как владелец индекса»: без постоянного посредника-разработчика
обновляется RAG дисциплины. Это снижает стоимость пилота LLM-тьютора и позволяет тиражировать
Loader на другие курсы ИЦО, меняя контент и идентификатор курса, а не код агентов.
